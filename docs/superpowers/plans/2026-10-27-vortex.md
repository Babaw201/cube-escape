# VORTEX implementation plan

**Goal:** Ship the seventh playable robot described in the user's VORTEX brief.
**Architecture:** Keep the existing game loop, damage, projectiles, save and host-authoritative input protocol. Add a small Three.js r128 module for the distinct procedural rig and bounded reusable gravity visuals. Gameplay stays in `index.html` beside the six existing kits.
**Spec:** The user's complete VORTEX mission (2026-10-26).
**Constraints:** No runtime dependencies; 5.5-unit radius, 3-second ultimate, 28-second cooldown; wave 20 in level 5; Spectre 50 and Souverain 100 unchanged. All five levels, two local players, host/guest, keyboard and touch.

## Review focus

- Dynamic walls closing during attraction must never push enemies into geometry.
- Guest snapshots must restore an ongoing effect without restarting its clock or duplicating damage.
- A fresh level/retry clears all pooled active effects and rig references.
- Malformed history must not grant rewards; valid historical records and existing entitlements survive.
- Disposing one player/preview must preserve another rig's shared resources.
